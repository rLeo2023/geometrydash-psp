Contexto de Desarrollo: Geometry Dash PSP (Port v2.0) - Parte 2

Esta continuación documenta la fase de estabilización, optimización de
rendimiento y corrección de bugs visuales específicos del port.

Estado del Proyecto

  - Performance (Gameplay): Gameplay estable a 60 FPS (Switch habilitado). El
    cuello de botella es el CPU (sprite creation / make phase), no el GPU.
  - Problemas resueltos:
      - Crash en arranque: Race condition en psp_log debido a escrituras
        concurrentes desde el hilo de audio e hilo principal al usar el mismo
        FILE*. Solucionado removiendo logs de hilo de audio y usando un
        mutex/flag global.
      - Stuttering en menús: Hitch de 266ms en menú de pausa y transiciones
        optimizado mediante el batching de actualizaciones de UI
        (ui_run_func_on_tags).
      - Visuales:
          - Bloques con gradientes (rainbow) y estelas de colores fixeadas
            mediante la aplicación correcta de per-object HSV (main_col_HSV,
            detail_col_HSV).
          - Portal exit de teletransporte (Deadlocked) validado.
          - Animación de monedas (User coins) restaurada mediante corrección en
            la lógica de Level Complete.
          - Icono estático de perfil funcional; removido ICON1.PMF (animado) del
            EBOOT por incompatibilidad con XMB.
      - Logging: Sistema de logs "always-on" pero ligero:
          - Logs críticos (perf ms, slow frame, boot milestones) activos por
            defecto.
          - Logs detallados gatillados por setting "Enable Debug Keys".
          - Escritura bufferizada para evitar I/O intenso en MS.

Análisis de Rendimiento (Log Actual)

  - Gameplay (Deadlocked): 60 FPS estables. Update: ~3-5 ms, Draw: ~2-4 ms,
    Vblank Wait: ~10 ms.
  - Puntos críticos:
      - Menú de Pausa: Aún presenta un hitch de ~266 ms (on-start). Es un
        problema de UI/UX, no de renderizado.
      - Level Complete (Primera vez): 35 ms de carga inicial (luego cacheado a 0
        ms).
      - Carga de Assets: El hardware PSP-1000 tiene limitaciones estrictas de
        RAM/IO. Canciones > 4 MB pueden fallar al cargar en memoria (se requiere
        streaming para música larga).

Pendientes Críticos

1.  Menú de Pausa (Hitch): Investigar el bloqueo de 266 ms tras la optimización
    de UI.
2.  UIList bug: Bug intermitente en la página de idiomas (ajuste de
    scroll/visibilidad de items).
3.  Memoria/Cargas: Implementar streaming de música si es requerido para
    canciones > 4MB (baja prioridad, alto riesgo).
4.  Limpieza final: Quitar logs de diagnóstico residuales antes del build de
    release.

Conclusiones Finales (Para exportar a otra IA)

El proyecto se encuentra en una fase de pulido final. El motor base de GD 2.0 es
funcional, estable a 60 FPS y con el rendimiento crítico resuelto. La
arquitectura actual es:

  - Renderizado: Citra2D adaptado (GE backend).
  - Optimización: Basada en culling dinámico, batching de UI y pre-caching de
    assets críticos.
  - Estabilidad: Se solucionaron los crashes de arranque (race condition en
    psp_log) y se implementó un sistema de logs robusto (opcional con debug
    keys).
  - Próximos Pasos sugeridos:
    1.  Investigar el hitch de entrada al menú de pausa (último hitch
        significativo).
    2.  Validar el comportamiento del UIList de settings en PSP físico.
    3.  Cerrar fase de optimización y preparar release final removiendo logs de
        debug innecesarios.

El proyecto NO requiere integración de GD 2.1 por solicitud expresa del usuario
(mantener fidelidad 2.0, sin spider/editor). Cualquier optimización adicional
debe priorizar la estabilidad de la memoria y la reducción de I/O en Memory
Stick.

Para que cualquier otra IA entienda cómo retomar el desarrollo, he consolidado
toda la información técnica, operativa y de los cambios críticos de la "Parte 2"
en este contexto exportable.

Contexto de Desarrollo: Geometry Dash PSP (Port v2.0) - Parte 2

Este documento resume el entorno de trabajo, el pipeline de compilación, la
estructura del proyecto y los cambios críticos realizados hasta la fecha
(23/10/2026).

1. Entorno y Pipeline de Build

  - Entorno: WSL2 (Ubuntu) con pspdev instalado en $HOME/pspdev.
  - Compilación:
      - Se utiliza make -f Makefile.psp en la raíz del proyecto.
      - El proceso genera un archivo gdpsp.elf y luego psp-prxgen crea el
        archivo .prx. Finalmente, pack-pbp genera el EBOOT.PBP.
  - Deploy (Despliegue):
      - El script make deploy (o pasos manuales) copia el EBOOT.PBP resultante y
        la carpeta romfs/ a la carpeta de pruebas en el disco local montado (ej.
        E:\Juegos PS2\gd20psp).
      - Estructura requerida en la PSP: ms0:/PSP/GAME/GeometryDashPSP/
        conteniendo:
          - EBOOT.PBP
          - romfs/ (todos los archivos de datos)
          - mstick/ (carpetas extra_levels/, saved_songs/, etc.)
  - Build IDs: Se añadió un build_id (fecha/hora) en el log (psp/src/build_id.c,
    regenerado automáticamente por el Makefile en cada build) para identificar
    qué versión corre en la consola.

2. Cambios Críticos (Resumen de la Parte 2)

  - Estabilidad (Fixes de Crash):
      - Race Condition: Se eliminaron las llamadas a psp_log desde hilos
        secundarios (audio thread, etc.) para evitar corrupción de memoria y
        crashes en vfprintf (address 0x01414149). Se introdujo un flag
        psp_main_thread para asegurar que el logging solo ocurra desde el hilo
        principal.
      - Corruption Log: Se eliminó el uso de LightLock de la compat layer
        de 3DS, ya que causaba corrupción en el formato de logs. Se utiliza
        ahora un logging single-threaded seguro.
  - Rendimiento:
      - Wave Trail: Optimizado para reconstruir el polígono una sola vez por
        frame (en UpdateWaveTrail), evitando N+1 reconstrucciones innecesarias.
      - Level Complete: Se precargan las pantallas de nivel completado al cargar
        el nivel, eliminando el stutter de 35ms en la primera completion.
      - Menú de Pausa: Optimizado mediante el batching de recorridos del árbol
        de UI (ui_run_func_on_tags) para reducir el costo de CPU al pausar.
      - Caches: Implementado cache por path para los MP3 para evitar re-lecturas
        constantes del Memory Stick.
  - Visuales/Bugs:
      - Glow: Fix aplicado: el glow ahora respeta el canal de color principal
        del objeto.
      - Coin Animation: Fix aplicado: ahora se anima correctamente en niveles
        custom/meltdown al recolectar nuevas monedas.
      - Teclado Perfil: Botón CANCEL reubicado para evitar superposiciones.
        Borrado el botón DEL (asignado a Square).

3. Estado de Diagnóstico (Log)

  - Configuración: Logging "Always-on" pero filtrado.
  - Nivel de detalle:
      - Básico: Siempre activo (perf ms, slow frame, boot milestones, svcBreak).
      - Detallado: Gatillado por settings "Enable Debug Keys".
  - Log actual: Indica que el gameplay corre a 60 FPS estables tras las
    optimizaciones. El menú de pausa sigue siendo el principal consumidor de
    tiempo (~60ms), aunque ya no es un problema bloqueante.

4. Pendientes para el Desarrollador

  - Hitch Menú de Pausa: Aunque optimizado, persiste un retraso. Se sospecha de
    ndspChnSetPaused o sincronización con el vsync.
  - UIList Bug: Error visual/lógico en la página de idiomas (ajuste de
    scroll/visibilidad de items). Se reportó que falta el botón de Portugués al
    scrollear.
  - Songs > 5MB: El motor MP3 actual (Media Engine) requiere el archivo completo
    en RAM. Para archivos grandes, es necesario implementar streaming de audio
    (librería mpg123 software) o recomendar canciones de menor bitrate.
